# Novyx Obsidian Plugin — v0.2.0 scope

Status: planning. v0.1.4 is in the marketplace queue. v0.2.0 ships once 0.1.x has been in users' hands for at least two weeks and we have at least one round of real user feedback.

## Goal

Expand the plugin from "Ghost Connections + Remember" into a full-featured Vault companion that exposes the parts of Novyx Core that matter inside an Obsidian session — without trying to replicate the full Vault app.

## Guiding principles

1. **Plugin features should be things that make sense inside a markdown editor.** If a feature is better as a standalone dashboard, it belongs in Vault, not the plugin.
2. **Read-mostly is fine.** Editing memories should still happen in Vault. The plugin is for inspecting, retrieving, and surfacing.
3. **Cross-vault memory sharing is the long-tail killer feature.** Every other v0.2 candidate is incremental. Sharing is the one that changes how people use it.
4. **Mobile is a first-class concern, not an afterthought.** The whole point of Obsidian is "your notes everywhere". A second brain that only works on desktop is a downgrade.

## Features

### 1. Mobile support — `isDesktopOnly: false`

**Status:** Investigation, then ship.

**Why:** v0.1 set `isDesktopOnly: true` because we couldn't verify the bundled Novyx SDK runs on iOS/Android Obsidian. The risk is the SDK pulling in node-only modules (`crypto`, `https`, `fs`) that don't exist in Obsidian's mobile JS environment.

**Approach:**
- Inspect the bundled `main.js` for `require('crypto')`, `require('https')`, etc.
- If clean, build a beta TestFlight/Android sideload and verify Ghost Connections + Remember work
- If dirty, work with the Novyx Core team to ship a browser-safe build of the SDK
- Once verified on real devices, flip the manifest flag

**Effort:** 1 day if SDK is clean, 1 week if it needs a rebuild.

**Blocks:** none.

### 2. Memory rollback timeline view

**Status:** Designed.

**Why:** Vault has the full rollback UI. The plugin should expose a lightweight version so users can roll back without leaving Obsidian. This is one of the differentiators we lead with — putting it one keystroke away matters.

**Scope:**
- New sidebar view: "Novyx: Memory Timeline"
- Shows the last 50 memory operations for the current vault, scoped by tag
- Each entry has a "Roll back to here" button
- Confirmation modal before rollback fires
- After rollback, refresh Ghost Connections automatically since the underlying memory state changed

**API surface needed:**
- `nx.replayTimeline({ tags, limit })` — already exists in SDK 3.2.0
- `nx.rollback({ to: <timestamp> })` — already exists

**Effort:** 2-3 days. New view + modal + sidebar wiring.

**Blocks:** none.

---

### 3. Cortex insights panel

**Status:** Scoped.

**Why:** Cortex surfaces emerging themes and patterns from the user's accumulated knowledge. In Vault it's a dashboard widget. In the plugin it should be a sidebar that shows "Patterns we noticed this week" — three-to-five sentences plus links to the notes that triggered each insight.

**Scope:**
- New sidebar view: "Novyx: Insights"
- Calls `nx.cortexInsights({ tags, since: 7d })` on open and on a manual refresh
- Renders each insight as a card with:
  - Theme/pattern title
  - Short description
  - "Source notes" expandable section linking to the notes that triggered it
- "Acknowledge" button that dismisses an insight (calls `nx.cortexAcknowledge`)
- Empty state for new vaults: "Cortex needs at least 20 memories before it can surface patterns"

**API surface needed:**
- `nx.cortexInsights()` — exists
- `nx.cortexAcknowledge(insightId)` — need to verify it's in 3.2.0

**Effort:** 3-4 days. Heavier render logic than rollback because insights are more complex objects.

**Blocks:** Verify cortexAcknowledge() is in JS SDK 3.2.0.

---

### 4. Audit trail browser

**Status:** Scoped, lower priority.

**Why:** The audit trail is a marketing differentiator we don't currently expose in the plugin. Users who care about it (compliance-conscious researchers, anyone running this for work) want to see it inside their notes app.

**Scope:**
- New sidebar view: "Novyx: Audit Trail"
- Shows the last 100 memory operations as a chronological list
- Each entry: timestamp, operation type, observation preview, hash (when present)
- Filter by operation type (remember/forget/rollback/etc.)
- "Verify chain" button that walks the chain and reports any tampering

**API surface needed:**
- `nx.audit({ limit, since })` — exists
- Chain verification logic (client-side hash chain walk)

**Effort:** 3-5 days. The chain verification UX is the tricky part — it has to be fast enough not to lock the UI for 1000+ entries.

**Blocks:** none. Could ship without verify-chain in v0.2 and add it in v0.3.

---

### 5. Cross-vault memory sharing (the killer feature)

**Status:** Strategic — needs Blake's call.

**Why:** Most Obsidian users have multiple vaults. Personal vault, work vault, research vault. They're isolated by design — that's a feature for security, but a tax on memory continuity. If you took notes about a topic in your personal vault and want to write about it in your research vault, the AI in the research vault has no idea.

Novyx Core already supports memory spaces and cross-space sharing. The plugin could expose this: "Share this memory with my research vault" / "Import shared memories from my personal vault".

**Scope:**
- Settings tab: list of "linked vaults" by tag
- New command: "Novyx: Share current note with linked vault" — picks a linked vault, copies the memory tag
- Ghost Connections sidebar option: "Include linked vaults" toggle
- Initial state: only the current vault's tag is queried (today's behavior)
- With toggle on: query includes linked vault tags, results are visually marked with the source vault

**API surface needed:**
- Already exists: tags are how Novyx Core scopes memories. The plugin just needs to manage the list of "linked vault tags" locally and pass them to `recall` when the toggle is on.
- No new Core API calls.

**Effort:** 1 week. Settings UI + sidebar toggle + visual differentiation of cross-vault results.

**Blocks:** none technically. Strategic question for Blake: do we want to encourage cross-vault memory mixing? The use case is clear but it has implications for the "memory hygiene" story we tell. Could be a Pro-tier feature.

---

### 6. Performance: cache Ghost Connections per note

**Status:** Quick win.

**Why:** Right now every note switch triggers a fresh `recall()` call. For users with hundreds of notes, this means hundreds of API calls per session. Most are cache-able — the note hasn't changed, the answer hasn't changed.

**Scope:**
- In-memory LRU cache keyed by `(notePath, content hash)`
- TTL: 5 minutes
- Cache invalidates when the user runs "Remember current note" (since the underlying memory state changed)
- Cache invalidates when settings change (threshold/limit)
- Settings toggle: "Cache Ghost Connections (recommended)"

**Effort:** 1 day.

**Blocks:** none.

---

### 7. Better orphaned-memory handling

**Status:** Polish.

**Why:** v0.1.x shows `(source note missing)` for memories whose file path no longer exists. That's correct but useless — users can't do anything about it. v0.2 should let them actually clean up.

**Scope:**
- Click an orphaned result in Ghost Connections → modal with three options:
  - "Forget this memory" (calls `nx.forget`)
  - "Re-link to a current note" (file picker)
  - "Keep as-is" (close)
- New command: "Novyx: Find all orphaned memories in this vault"

**Effort:** 1-2 days.

**Blocks:** none.

---

## v0.2.0 minimum bar

The features above are ranked by impact. Minimum scope for v0.2.0 to feel like a meaningful release:

1. **Mobile support** (#1) — table stakes for an Obsidian plugin
2. **Memory rollback timeline** (#2) — biggest visible differentiator
3. **Performance: ghost connection cache** (#6) — quality-of-life

That's three features, ~1-2 weeks of work.

Cortex insights (#3), audit browser (#4), and orphaned memory handling (#7) can ship in v0.2.1 or v0.3.

Cross-vault sharing (#5) is its own release — v0.3.0 with strategic positioning around it.

## Open questions for Blake

1. **Pro-tier features in the plugin?** The plugin is currently 100% free (BYOK). Should rollback timeline, Cortex insights, or cross-vault sharing be gated behind a Novyx Pro tier? My recommendation: keep the plugin entirely free, but the underlying API endpoints are already tier-gated server-side (rollback monthly limits, cortex requires Pro). The plugin just calls the APIs and displays whatever the user's tier allows. No client-side gating.

2. **Cross-vault sharing — strategic call.** Worth discussing before I scope it deeper. The technical side is easy. The product question is whether this is the killer feature we lead with or a power-user toggle.

3. **Mobile timeline.** If the SDK is clean, mobile lands in week 1 of v0.2 work. If it isn't, do we want to wait for the Novyx team to ship a browser-safe build, or ship v0.2 desktop-only and flip in v0.2.1?

## Anti-features (explicitly not in v0.2.0)

- **Markdown editor improvements** — Obsidian's editor is already great. We don't compete here.
- **Syncing memories to Obsidian Sync** — different storage layer, would create user confusion
- **Voice capture** — Vault has this, the plugin shouldn't try
- **Knowledge graph rendering** — Obsidian has its own graph view, our `Ghost Connections` sidebar is the right surface for "find me related notes"
- **Multi-LLM provider switching** — we use the Novyx SDK which routes to whatever the user has configured server-side. Provider switching belongs in the Novyx Core dashboard, not the plugin.
